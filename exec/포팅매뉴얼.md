## 2. 빌드 시 사용되는 환경 변수

환경 변수는 **두 곳**에서 읽는다. 둘 다 `.gitignore` 대상이라 저장소에 없으며, 각각의
`.env.example`을 복사해 값을 채운다.

```bash
cp .env.example .env                      # 백엔드·인프라용
cp frontend/.env.example frontend/.env    # 프론트용
```

### 2-1. 루트 `.env` — 백엔드·인프라

| 키 | 용도 | 필수 | 비고 |
|---|---|---|---|
| `DB_PASSWORD` | MySQL root 비밀번호 | ✅ | compose가 DB 초기화에 사용 |
| `JWT_SECRET` | JWT 서명 키 | ✅ | 충분히 긴 랜덤 문자열 |
| `OAUTH_GOOGLE_CLIENT_ID` | 구글 소셜 로그인 | ✅ | 3-1 참조 |
| `OAUTH_GOOGLE_CLIENT_SECRET` | 구글 소셜 로그인 | ✅ | **프론트에 두지 않음** |
| `MINIO_ACCESS_KEY` | MinIO 접속 | ✅ | compose의 minio 서비스 값과 **반드시 일치** |
| `MINIO_SECRET_KEY` | MinIO 접속 | ✅ | 불일치 시 업로드 인증 실패 |
| `OAUTH_GITHUB_CLIENT_ID` | GitHub 연동(잔디) | 선택 | 3-2 참조 |
| `OAUTH_GITHUB_CLIENT_SECRET` | GitHub 연동 | 선택 | |
| `GITHUB_TOKEN_ENC_KEY` | GitHub 토큰 암호화 | 선택 | Base64 32바이트 · `openssl rand -base64 32` |
| `OAUTH_GITHUB_REDIRECT_URI` | GitHub 콜백 | 선택 | OAuth App 등록값과 **문자 하나까지 동일**해야 함 |
| `APP_FRONT_BASE_URL` | 연동 후 복귀 주소 | 선택 | 뒤에 `/users/{userId}`가 붙는다 |
| `OPENAI_API_KEY` | 게시물 AI 요약 | 선택 | SSAFY GMS 키. 비우면 요약 없이 저장만 됨 |
| `OPENAI_MODEL` | 요약 모델명 | 선택 | 게시물마다 호출되어 비용 누적 |
| `AWS_ACCESS_KEY_ID` / `AWS_SECRET_ACCESS_KEY` | 실제 AWS SQS 사용 시 | 선택 | ElasticMQ 사용 시 불필요 |

**주의 사항**

- `GITHUB_TOKEN_ENC_KEY`를 변경하면 **저장된 GitHub 토큰을 복호화할 수 없어** 전 사용자 재연동이 필요하다.
- `MINIO_ACCESS_KEY` / `MINIO_SECRET_KEY`가 compose의 minio 서비스 기본값과 다르면 백엔드가 빈 값으로 접속해 인증에 실패한다.
- 선택 항목을 비워두면 **해당 기능만 동작하지 않고 앱은 정상 기동**한다(장애 격리 적용됨).

### 2-2. `frontend/.env` — 프론트

| 키 | 용도 | 값 |
|---|---|---|
| `VITE_GOOGLE_CLIENT_ID` | 구글 OAuth Client **ID만** | Client Secret은 절대 넣지 않는다 |
| `VITE_USE_MOCK` | msw API 모킹 | 배포 시 **`false`** (기본값). 로컬 개발용 |

> `VITE_` 접두어가 붙은 값은 **빌드 시점에 번들에 박힌다.** 비밀값을 넣지 않는다.
> `VITE_USE_MOCK=true`인 채로 빌드하면 목 데이터가 화면에 나오므로 배포 전 반드시 확인한다.

## 3. 외부 서비스 — 가입 및 설정

프로젝트가 사용하는 외부 서비스는 **두 개**다(둘 다 무료).

### 3-1. Google OAuth 2.0 — 소셜 로그인 (필수)

1. [Google Cloud Console](https://console.cloud.google.com/) → 프로젝트 생성
2. **API 및 서비스 → OAuth 동의 화면** 구성 (외부, 테스트 사용자 등록)
3. **사용자 인증 정보 → OAuth 클라이언트 ID 만들기 → 웹 애플리케이션**
4. **승인된 리디렉션 URI**에 등록
   ```
   http://localhost:3000/oauth/callback/google      (로컬)
   https://{배포도메인}/oauth/callback/google        (운영)
   ```
5. 발급된 값을 배치
   - `Client ID` → 루트 `.env`의 `OAUTH_GOOGLE_CLIENT_ID` **및** `frontend/.env`의 `VITE_GOOGLE_CLIENT_ID`
   - `Client Secret` → 루트 `.env`의 `OAUTH_GOOGLE_CLIENT_SECRET` (**프론트에 넣지 않음**)

### 3-2. GitHub OAuth App — 잔디·기술스택 연동 (선택)

1. GitHub → **Settings → Developer settings → OAuth Apps → New OAuth App**
2. **Authorization callback URL** 등록 — 콜백을 **백엔드가 받는다**
   ```
   http://localhost:3000/api/github/callback         (로컬)
   https://{배포도메인}/api/github/callback           (운영)
   ```
   > OAuth App은 콜백 URL을 하나만 받으므로 **로컬용·운영용 앱을 따로 만든다.**
3. 발급값을 `.env`의 `OAUTH_GITHUB_CLIENT_ID` / `OAUTH_GITHUB_CLIENT_SECRET`에 넣는다.
4. `GITHUB_TOKEN_ENC_KEY` 생성 — `openssl rand -base64 32`
5. `OAUTH_GITHUB_REDIRECT_URI`를 2번에 등록한 값과 **완전히 동일**하게 기재
6. `APP_FRONT_BASE_URL`에 프론트 주소 기재 (예: `http://localhost:3000`)

- 요청 scope: `read:user repo` (비공개 저장소 커밋 집계용)
- 미설정 시: 프로필의 GitHub 활동 영역에 **연동 안내 문구**가 표시되고 나머지는 정상 동작

### 3-3. SSAFY GMS (OpenAI 호환) — 게시물 AI 요약 (선택)

- `OPENAI_API_KEY`에 **SSAFY GMS 발급 키**를 넣는다(OpenAI 직접 발급 키 아님).
- `OPENAI_MODEL`에 사용할 모델명을 기재.
- 미설정 시: 요약 없이 게시물만 저장된다.

### 3-4. 사용하지 않는 것

- Photon Cloud, 외부 코드 컴파일 서비스 등은 **사용하지 않는다.**
- 파일 저장소는 외부 S3가 아니라 **자체 호스팅 MinIO**를 쓴다(가입 불필요).

## 4. 빌드 및 배포 절차

### 4-1. 전체 실행 (권장 · Docker Compose)

```bash
# 1) 저장소 클론
git clone {저장소 URL}
cd S15P11E204

# 2) 환경 변수 준비
cp .env.example .env
cp frontend/.env.example frontend/.env
#   → 두 파일의 값을 3장 안내대로 채운다

# 3) 전체 기동 (이미지 빌드 포함)
docker compose up -d --build

# 4) 상태 확인
docker compose ps
docker logs helloworld-backend --tail 50
```

접속 주소

| 대상 | 주소 |
|---|---|
| 서비스 | `http://localhost:3000` |
| 백엔드 API | `http://localhost:8080/api/...` |
| MinIO 콘솔 | `http://localhost:9001` |

### 4-2. 개별 빌드 (로컬 개발)

**백엔드**
```bash
cd backend
mvn clean package -DskipTests     # target/*.jar 생성
java -jar target/*.jar
```

**프론트**
```bash
cd frontend
npm ci
npm run dev      # 개발 서버 — http://localhost:3000
npm run build    # 프로덕션 빌드 (tsc -b && vite build) → dist/
npm run lint     # oxlint
```

> `npm run build`는 **타입 에러가 있으면 실패**한다(`tsc -b`가 선행).

### 4-3. DB 초기화

```bash
# 1) 스키마
docker exec -i helloworld-mysql mysql -uroot -p{DB_PASSWORD} helloworld \
  < backend/src/main/resources/schema.sql

# 2) 마이그레이션 — 번호 순서대로 전부 적용
for f in backend/src/main/resources/migration/0*.sql; do
  docker exec -i helloworld-mysql mysql -uroot -p{DB_PASSWORD} helloworld < "$f"
done
```

또는 **DB 덤프 파일**(`exec/` 폴더 내)을 복원한다 — 5장 참조.

마이그레이션 목록 (`backend/src/main/resources/migration/`)

```
001_add_users_introduce.sql              007_drop_dm_members_unused_columns.sql
002_seed_tags.sql                        008_add_posts_content_fulltext_ngram.sql
003_drop_users_exp_point_level.sql       009_add_search_histories_unique.sql
004_add_dm_messages_client_message_id    010_add_comments_like_count.sql
005_add_dm_messages_room_msg_index.sql   011_add_github_tables.sql
006_add_post_likes_cursor_indexes.sql
```

> 적용 이력은 `migration/README.md`에 기록한다. **표와 실제 DB가 어긋난 적이 있어**,
> 판단이 필요하면 `information_schema`를 직접 조회하는 것을 규칙으로 둔다.

### 4-4. 배포 시 특이사항 ⚠️

**① 프론트 포트는 3000 고정**
`frontend/vite.config.ts`에 `port: 3000, strictPort: true`가 설정되어 있다.
백엔드 CORS 허용 오리진과 OAuth 리디렉션 URI가 모두 3000 기준이므로 **다른 포트로 바꾸면 로그인·연동이 깨진다.**

**② 프론트와 백엔드는 같은 오리진으로 서빙**
nginx가 정적 파일과 `/api`를 함께 서빙한다(`proxy_pass http://backend:8080`).
개발 환경도 Vite 프록시로 같은 오리진을 유지한다. **API는 항상 상대경로(`/api/...`)로 호출**한다.

**③ WebSocket 경로 프록시 필수**
채팅·알림이 STOMP(`/ws`)를 사용한다. 리버스 프록시에 WebSocket 업그레이드 설정이 없으면 실시간 기능이 동작하지 않는다.

**④ 단일 서버 전제**
STOMP 브로커가 스프링 내장 SimpleBroker(인메모리)다. **서버를 여러 대로 늘리면 서버 간 메시지가 전달되지 않는다.** 확장 시 외부 브로커(RabbitMQ 등) 릴레이로 교체해야 한다.

**⑤ Redis 영속화**
AOF + named volume으로 재기동 시 좋아요·팔로우 데이터가 복원된다. **볼륨을 삭제하면 복구 지점이 사라진다.**

**⑥ 선택 기능 미설정 시에도 기동**
MinIO·GitHub·AI 요약 설정이 비어 있어도 앱은 정상 기동하고 **해당 기능만 실패**한다.
(과거 파일 저장소 설정 누락으로 앱 전체가 크래시 루프에 빠져 운영 2분 중단을 겪은 뒤 적용한 구조)

**⑦ 코드 변경 후 재배포**
컨테이너는 빌드된 이미지를 실행하므로 소스만 고쳐도 반영되지 않는다.
```bash
docker compose up -d --build backend    # 또는 frontend
```

## 6. 이 폴더(`exec/`)의 구성

| 파일 | 설명 |
|---|---|
| `포팅매뉴얼.md` | 이 문서 — 빌드·배포·환경변수·외부서비스 |
| `시연시나리오.md` | 화면별 시연 순서와 클릭 위치 |
| `helloworld_dump.sql` | DB 덤프 최신본 |

### DB 덤프 생성·복원

```bash
# 생성
docker exec helloworld-mysql mysqldump -uroot -p{DB_PASSWORD} \
  --databases helloworld --routines --single-transaction > exec/helloworld_dump.sql

# 복원
docker exec -i helloworld-mysql mysql -uroot -p{DB_PASSWORD} < exec/helloworld_dump.sql
```
